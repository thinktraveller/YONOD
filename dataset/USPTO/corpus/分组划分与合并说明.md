## 2. 原始数据如何分组并划分集合

Schwaller 等人在 2018 年论文 *Found in Translation* 第 3 节中说明：对处理后的单产物反应数据进行随机划分，训练、验证和测试的目标比例为 **18∶1∶1（约 90%∶5%∶5%）**；**反应物相同、但试剂或产物不同的反应保留在同一个集合中**。

这里需要区分两个概念：

- **反应物组**：具有相同反应物的相关反应记录。每条记录仍然是独立样本，不会因为同组就取平均、合成一条记录或合并产率。
- **训练/验证/测试集合**：分配给不同建模用途的数据分区。同一个反应物组不能被拆散到不同集合。

例如，`A + B → P1` 和 `A + B → P2` 即使试剂、产物或产率不同，也应留在同一个集合。`A + C → P3` 不因与前两条共享单个反应物 A 就自动归为同组；这里指相同的反应物组合，而不是共享任意一个分子。

因此，原协议是**带相同反应物同组约束的随机划分**，不是逐行独立抽签。论文没有将这三个集合描述为按年份、骨架或高低产率特意挑选的划分；该论文另外使用的 2017 年 Pistachio 时间外推测试是另一个数据集。

**可复现性边界：**当前证据明确支持上述分组约束和目标比例，但尚未确认作者实际划分实现中的随机种子、组内代表键、分子标准化细节及比例分配算法。本地没有可据以逐条重建原始划分的完整脚本，不能将某个新写的 GroupShuffleSplit 实现称为原作者算法。保留 `split` 才能精确保留当前快照的集合归属。

## 3. “随机划分”与“筛选数据”同时存在

数据处理链为：

1. Lowe 从美国专利文本提取反应。
2. Schwaller 等去除重复及不能规范化的反应，选取单产物反应，并按上述规则划分集合。
3. Minidis 发布产率清洗版本，对已有文件的产率字段进行清洗、筛选。公开清洗脚本没有重新划分集合的逻辑。
4. 本项目将本地原始 TSV 转换为统一七列标准 CSV，保留原集合归属。
5. 本次把三个标准 CSV 拼接为 `merged.csv`。

产率清洗的主要规则是：排除无可用产率的记录；只接受大于 0 且不超过 100 的候选数值；文本提取产率和计算产率都可用时取较大者；范围产率取上界；删除原专利号、年份等部分元数据列。详细处理以公开脚本为准。

所以合并后的总体已经经过筛选，不是未经筛选的全部专利反应，也不能将其产率一概视作未经处理的实测值。分组和后续过滤也意味着最终行数无需严格等于 90%/5%/5%。没有发现专门把某种产率或反应类型挑入验证集的依据。

## 4. 合并时保留的字段

合并文件为 UTF-8、逗号分隔 CSV，只有一行表头，不写入 Pandas 索引。七个字段及顺序均保持不变：

| 字段 | 含义与本次处理 |
| --- | --- |
| `sample_id` | 原样保留的全局唯一样本 ID，格式为 `uspto_<split>_<myID>`。原始 myID 会跨集合重复，不单独用作全局主键。 |
| `split` | 原样保留 `train`、`valid`、`test`，表示原集合归属；合并后没有将其统一改成 train。 |
| `reactants_smiles` | 原样保留反应物区段，包括点号连接的多组分。 |
| `reagents_smiles` | 原样保留试剂区段；空字段继续为空，不填入虚构分子。 |
| `products_smiles` | 原样保留产物区段。 |
| `yield_percent` | 保留原 CSV 中的产率文本，不缩放、取整或重新聚合。 |
| `reaction_smiles` | 原样保留完整反应字符串，用于溯源和审计。 |

读入时将各列作为字符串并禁止自动把空值转换成 NaN，再按行拼接。写出后重新读取，已对全部 526,468 行的七列逐字段验证一致。

原始记录可通过 `sample_id` 关联本目录的 `provenance.csv`，找到源文件、源行号、源索引和源 myID。本次没有生成新的分组编号，也没有修改溯源表。

本次检查结果：

- 三份标准表字段及顺序一致，`split` 与文件名一致。
- 合并后 `sample_id` 全局唯一。

## 6. 合并后的集合使用

统一读取和统计可直接使用 `merged.csv`。复现原划分时按 `split` 筛选：train 用于拟合，valid 用于调参与模型选择，test 用于最终评估。`sample_id` 和 `split` 是标识/划分字段，不作为预测特征。

如果为新研究重新划分，应另行保存新划分并说明协议，至少考虑保持相同反应物的分组隔离。普通逐行随机划分或 KFold 可能将相关反应分到不同集合，不能称为复现原有测试结果。当前 YONOD 普通 KFold 工作流不会仅凭 CSV 中存在 `split` 列就自动执行原固定划分。
