# chemical_vae 原理与 YONOD 参考价值

初始源码核查日期：2026-09-14。本文的上游架构说明仍基于本地源码静态阅读；其后的 YONOD 接入状态以本节为准，不能把历史段落中的“待接入”表述当作当前实现状态。

## YONOD 当前接入状态（2026-09-14）

- 已支持两个分别验收的 encoder 变体：ZINC/v5 和 `zinc_properties` encoder/v5。`chemical_vae` 只读取各自 manifest 相邻、内容哈希校验的 PyTorch state；两者的源 HDF5 SHA-256 不同，不能互相替代。输出是原始、确定性的 `z_mean_sample`，每个分子 196 维。
- 普通运行时是 PyTorch CPU 或已实测的 `cuda:0` 路径；不读取原 HDF5、TensorFlow/Keras、解码器、TerminalGRU、性质头或训练 CSV。`tensorflow-cpu==2.15.1` 仅用于保存于 `derived/chemical_vae/step31_3_parity/` 的历史 HDF5 数值对照，非特征生成依赖。
- 输入是 identity 文本：不 trim、canonicalize、拆盐、截断或扩字符表。适配器对长度（最多120）、冻结35字符表与 RDKit 可解析性逐行预检，保存完整 diagnostics sidecar；`concat` 的单角色失败为零块，严格共同子集必须显式要求所有角色成功。
- 已有 Linux CPU 的真实 features→train/all smoke、12 行 VAE/Morgan/MFP 配对工程证据，以及 `cuda:0` 的 ZINC/v5 和 `zinc_properties` encoder VAE×RF smoke；它们不是发表级性能结论。`zinc_properties` 的 decoder/性质头/训练/生成仍不支持。用户已授权将步骤31标记完成并延期 Windows CPU 验证；Windows CPU 本身仍是 `not_verified`，交接程序不冒充平台实测。详见 [C11 verification](../derived/chemical_vae/step31_9_gpu_smoke/verification.json)、[Windows handoff](chemical-vae-platform-handoff.md)、[31.7 comparison](../derived/chemical_vae/step31_7_comparison/comparison_report.json) 和 [acceptance index](../derived/chemical_vae/step31_acceptance/index.json)。

## 原理

模型把离散的 SMILES 字符序列映射到连续潜空间，并学习从潜空间恢复 SMILES。整体由编码器、变分采样、解码器和可选性质预测头构成。

1. **字符输入**：SMILES 按固定字符表做 one-hot，并补齐到固定长度。仓库两个 ZINC 示例都使用最大长度 120、35 个字符。
2. **编码器**：一维卷积提取字符序列模式，全连接层得到潜变量均值；变分分支由编码器中间输出预测对数方差。ZINC 示例的潜变量维度是 196，不能把它误认为所有配置的固定维数。
3. **变分训练**：标准 VAE 用 `z = μ + σ ⊙ ε` 实现可反向传播的采样；本实现还将退火系数乘到噪声项，推理阶段使用均值。
4. **解码器**：将潜向量重复到序列长度，经多层 GRU 和自定义 TerminalGRU 输出字符概率。训练使用真实前序字符辅助预测（teacher forcing），生成时需依靠模型自身输出。
5. **性质监督**：可选的多层感知机从潜表示预测性质；`zinc_properties/exp.json` 指定 QED、SAS、logP，均不是反应产率。

训练目标可概括为：

`L = a × SMILES重构交叉熵 + β(t) × KL(q(z|x) || N(0,I)) + λ × 性质预测误差`

其中重构项要求保留结构信息，KL 项约束潜分布，性质误差引导表示保留与指定性质相关的信息。KL 权重逐步增加，避免训练初期正则项过强；性质头关闭时无第三项。该式是概念表达，实际权重组合见 `train_vae.py`。

有了连续表示，就能对分子做邻域扰动、插值，或优化性质代理模型后再解码候选结构。这是论文的分子设计思路，并不保证任意潜向量都能解码成有效、可合成或符合反应约束的分子。

## 详细转换示例：从一个 SMILES 到潜向量，再到分子

以下以乙醇 SMILES `CCO` 为例，串联 chemical_vae 的输入、内部张量和输出。示例中的张量形状与本地 `models/zinc/exp.json`、`models/zinc/zinc.json` 一致；表中的潜向量数值和字符概率仅为说明而设，**并非实际运行该预训练模型得到的结果**。

### 1. 原始输入

编码器接收的是分子 SMILES 字符串，单个分子或一批分子均可输入：

```python
smiles = ["CCO", "CC(=O)O"]
#          乙醇     乙酸
```

这里的输入只描述分子结构；反应产率、温度、时间和催化剂类别不会自动包含在 SMILES 中。ZINC 示例的相关固定参数为：

| 参数 | 值 | 作用 |
|---|---:|---|
| `MAX_LEN` | 120 | 资产输入长度；当前 YONOD 对超长输入明确失败，不截断 |
| `NCHARS` | 35 | 字符表中的字符类别数 |
| `hidden_dim` | 196 | 每个分子产生的潜向量维度 |

字符级表示不等于原子级表示。例如 `Cl` 会被看作字符 `C` 和 `l`，括号、环编号和键符号也分别占一个位置。

### 2. 字符 one-hot 编码

`CCO` 先按右侧填充到长度 120：

```text
原始：C C O
补齐：C C O □ □ □ □ … □
      └────── 120 个位置 ──────┘

□ 是字符表中的空格填充符。
```

随后，每个字符位置变为一个 35 维 one-hot 向量。下面只显示完整 35 个列中的 `C`、`O` 和空格列：

| 序列位置 | 字符 | `C` 列 | `O` 列 | 空格列 | 其他 32 列 |
|---|---|---:|---:|---:|---|
| 1 | `C` | 1 | 0 | 0 | 均为 0 |
| 2 | `C` | 1 | 0 | 0 | 均为 0 |
| 3 | `O` | 0 | 1 | 0 | 均为 0 |
| 4–120 | 空格 | 0 | 0 | 1 | 均为 0 |

因此，一个 `CCO` 输入的张量形状是 `(1, 120, 35)`；示例中的两个分子共同输入时，形状为 `(2, 120, 35)`。这一阶段只是把文本转为数值矩阵，尚未形成化学表示。

### 3. 编码器和 VAE 潜向量

编码器先以一维卷积提取局部字符模式，再经全连接层汇总成分子级表示：

```text
one-hot SMILES
(2, 120, 35)
       │
       ▼
多层一维卷积、展平、全连接层
       │
       ├── 潜变量均值 μ:      (2, 196)
       └── 潜变量对数方差:    (2, 196)
```

可将 `μ` 的输出理解成下表。第 1、2、3 个维度不是分子量、极性等预先定义的化学量；它们是模型共同学习出的连续特征。

| 分子 | `z₁` | `z₂` | `z₃` | … | `z₁₉₆` |
|---|---:|---:|---:|---|---:|
| `CCO` | 0.12 | -0.47 | 0.83 | … | 0.06 |
| `CC(=O)O` | 0.19 | -0.32 | 0.71 | … | -0.14 |

训练时，VAE 按下式从均值与方差中采样：

`z = μ + σ ⊙ ε`，其中 `ε ~ N(0, I)`。

这使解码器学习在邻近潜空间中恢复合理的分子。该实现还通过退火权重逐渐提高 KL 正则的影响。推理时使用均值向量 `μ`，因而同一 SMILES 在固定权重与预处理下可产生稳定的描述符。需要注意，`VAEUtils.encode()` 默认还会以其自身估计的均值和标准差标准化 `μ`；接入 YONOD 时应明确选用原始 `z_mean` 或固定版本的标准化向量，不能混用。

### 4. 从潜向量解码回 SMILES

为了重构或生成分子，196 维潜向量被送入解码器：

```text
潜向量 z
(1, 196)
       │
       ▼
全连接层、沿序列长度复制、多层 GRU / TerminalGRU
       │
       ▼
每个位置对 35 个字符的概率
(1, 120, 35)
       │
       ▼
逐位置选择或采样字符，去除末尾填充空格
       │
       ▼
SMILES
```

例如，一个理想化的解码结果可写为：

| 位置 | 部分字符概率示例 | 选出的字符 |
|---|---|---|
| 1 | `C: 0.90, O: 0.04, …` | `C` |
| 2 | `C: 0.85, O: 0.08, …` | `C` |
| 3 | `O: 0.80, C: 0.12, …` | `O` |
| 4 | `空格: 0.95, …` | 空格 |
| 5–120 | 空格概率较高 | 空格 |

去掉填充后得到 `CCO`。完整理想路径为：

```text
CCO → (1, 120, 35) one-hot → (1, 196) 潜向量 → (1, 120, 35) 字符概率 → CCO
```

真实生成并不保证逐字符还原输入，也不保证 SMILES 合法。因此生成结果应通过 RDKit 重新解析、规范化，再进行结构级比较和化学筛选。

### 5. 训练信号如何约束这一转换

以 `CCO` 为输入时，模型至少包含重构损失和 KL 正则；打开性质预测头时还有性质误差：

| 训练项 | 输入和监督目标 | 作用 |
|---|---|---|
| 重构误差 | 输入 `CCO`，目标仍为 `CCO` | 要求潜向量保留足以还原分子结构的信息 |
| KL 正则 | 约束潜变量分布 | 使潜空间连续并便于采样、扰动和插值 |
| 可选性质误差 | 从潜向量预测训练数据中提供的标签 | 引导潜向量保留与这些标签相关的信息 |

性质监督的结构如下：

```text
SMILES → 编码器 → 潜表示 ─→ 解码器 → 重构 SMILES
                         └→ 性质预测头 → [QED, SAS, logP]
```

本仓库提供的性质头输出 `QED`、`SAS`、`logP`，而不是反应产率。因此，没有额外训练时，它不能把某个 196 维向量直接变成 YONOD 任务的产率预测。

## 详细转换示例：接入一条 YONOD 反应记录

反应产率是多个组分与反应条件的共同结果。以一条简化的 Suzuki 偶联记录为例，下面的条件与产率仅用于说明字段组织：

| 字段 | 示例值 |
|---|---|
| 底物 1 | `Brc1ccccc1`（溴苯） |
| 底物 2 | `OB(O)c1ccccc1`（苯硼酸） |
| 溶剂 | `CCO`（乙醇） |
| 催化剂类别 | 数据集中的催化剂标识 |
| 温度 | `80` |
| 时间 | `2` |
| 产率 | 训练时已知的实验标签；预测时未知 |

若三个 SMILES 都能通过预检和编码器，各自取一个 196 维 `μ`：

```text
Brc1ccccc1     → μ₁: 196 维
OB(O)c1ccccc1  → μ₂: 196 维
CCO            → μ₃: 196 维

反应结构特征 = [μ₁ | μ₂ | μ₃] = 588 维
```

随后拼入反应条件，形成 YONOD 的回归输入：

```text
X = [588 维分子特征 | 温度 | 时间 | 催化剂类别的训练折 OHE 特征]
X → RandomForest / XGBoost / 其他回归器 → 预测产率 ŷ
```

若当前训练折的催化剂 OHE 占 `k` 列，则该行输入形状为 `(1, 590 + k)`。训练时使用多条记录的 `X` 和实验产率 `y` 拟合回归器；预测时只提供结构与条件。本路线只需要冻结编码器，不需要 chemical_vae 解码器。

若有六个分子输入列，同样的逐列拼接会形成 `6 × 196 = 1176` 维分子部分。必须保持各列角色和顺序，例如不能把配体向量与溶剂向量互换；也不能把同一条反应的产率标签分配给各单独组分，当作其固有性质。

### 输入失败的具体例子

RDKit 能解析输入，与 chemical_vae 的字符表能编码输入，是两个不同问题。当前 ZINC 字符表不包含 `.`、`i`、`d`：

| 原始输入 | 失败原因 | 适配器应有的结果 |
|---|---|---|
| `[Ni]` | 小写 `i` 不在字符表中 | 标记 `False` 和 `unsupported_character:i` |
| `[Pd]` | 小写 `d` 不在字符表中 | 标记 `False` 和 `unsupported_character:d` |
| `CCO.CC` | `.` 不在字符表中 | 标记 `False` 和 `unsupported_character:.` |
| 长度大于 120 的 SMILES | 超过示例模型输入上限 | 标记 `False` 和 `length_exceeded` |

YONOD 的描述符接口应保持行对齐，而不是让上游函数静默过滤样本。目标行为例如：

```python
inputs = ["CCO", "[Ni]", "CC(=O)O"]

features.shape  # (3, 196)
mask            # [True, False, True]
```

失败行可用零向量占位，但必须同时保存 `mask`、失败原因和原始 `sample_id`，并由显式的数据策略决定是排除该反应、保留零块，还是使用另一种描述符。否则零向量会被误当作正常的镍催化剂特征，或因静默删行造成标签错位。

## 对 YONOD 的价值判断

以下是结合本地 YONOD 接口提出的方案，尚无本项目实验支持其精度收益。

| 用途 | 如何结合 YONOD | 优先级与边界 |
|---|---|---|
| 增加学习型描述符对照 | 冻结编码器，提取每个组分的 196 维均值向量，按反应角色拼接，再输入 RF/XGBoost 等回归器 | 最直接；与 Morgan/MFP、FISD、MolMetaLM 在同一划分和样本集比较 |
| 研究性质监督的作用 | 对比纯重构和带性质监督两个表示，考察是否改善产率预测 | 值得研究；现有两套权重训练条件不完全相同，不能直接把差异归因于性质监督 |
| 化学空间分析 | 分析底物、配体在潜空间中的邻近关系，辅助定位高误差或分布外样本 | 探索工具；潜距离及方差不等同于校准后的产率不确定性 |
| 候选配体/底物设计 | 固定其他反应条件，搜索某个组分的潜向量，解码候选后用产率模型排序 | 后续研究；还需有效性、反应适配性及可合成性筛选和实验验证 |

反应产率由多个组分和条件共同决定。可行的预测结构是：

`[μ(底物1), μ(底物2), μ(配体), …, 温度, 时间, 类别条件] → 产率回归器`

若有六个分子输入列，单纯拼接对应 `6 × 196 = 1176` 维，另加条件特征。不能把同一个产率标签直接分配给每个单独分子当成其固有性质。若进行产率监督的表示训练，应建立反应级预测头。

## 源码中与接入直接相关的限制

- **运行栈很旧**：`requirements.txt` 固定 Keras 2.0.7、TensorFlow GPU 1.1.0、pandas 0.19.2；不能直接视为适配 YONOD Python 3.9 的组件。若要落地，先评估隔离复现或编码器迁移，并核对迁移前后向量的一致性。
- **字符覆盖不足**：示例字符表没有 `.`、`i`、`d`，因此点分隔盐/多组分，以及 `[Ni]`、`[Pd]` 等输入无法原样编码。字符均在表内也不代表模型学过该类化学结构。对 YONOD 的金属催化反应，需首先统计各角色的字符、长度和化学域覆盖率。
- **超长输入会被过滤**：`mol_utils.smiles_to_hot` 会跳过超过最大长度的序列，未知字符则抛出错误。直接包装会有丢行或样本错位风险。适配器应预检，按原始位置输出特征及失败 mask，明确区分缺失组分与编码失败。
- **工具类有额外工作**：`VAEUtils.__init__` 会同时加载解码器、读取数据、随机抽样估计潜变量标准化参数，并临时改变工作目录。仅提取描述符时应做轻量编码器包装，避免这些隐式操作；需要标准化时固定外部统计量，或仅在训练折拟合。
- **生成目标与预测目标不同**：重构 SMILES 或预测 logP/QED/SAS 的成功，不能直接证明反应产率预测会提升。配体、催化剂、试剂与 ZINC 类药分子之间存在需要评估的分布差异。

## 建议的接入与验证顺序

1. 先审计代表性 YONOD 数据集，按角色统计有效 RDKit SMILES、长度不超过 120、字符可编码的比例，保留 `sample_id` 和失败原因。禁止用静默截断或随意删掉金属片段来提高覆盖率。
2. 只提取冻结编码器的原始 `z_mean`，包装为 `BaseDescriptor.featurize(smiles_list) -> (features, mask)`。批处理唯一 SMILES 并缓存，保证重复调用结果稳定。
3. 接入实现不只是一个描述符类：`yonod/descriptors/registry.py` 的 provider/参数校验、`yonod/universal/feature_builder.py` 的工厂参数传递，以及 `yonod/pipeline/features.py` 的缓存前资产身份核验都已完成。当前只开放分别验收的 `chemical_vae` ZINC/v5 与 `zinc_properties` encoder/v5；其他变体、以及 `zinc_properties` 的性质头保持不可选。
4. 把权重内容哈希、字符表及顺序、MAX_LEN、规范化规则、输出维度与实现版本纳入特征身份。冻结且不依赖目标数据拟合的编码器可以进入静态特征生命周期；使用 YONOD 数据拟合/微调的版本必须按评估协议在训练折内处理。
5. 固定相同 `sample_id` 交集、标签和外层划分，与 Morgan/MFP、FISD、MolMetaLM 比较 R²、MAE、RMSE、覆盖率、特征生成耗时。共同子集上的性能与全量覆盖率分开报告，防止失败过滤造成虚假的指标改善。缩放、PCA、调参和早停仅使用训练折。
6. 若做严格归因实验，纯 VAE 与性质监督 VAE 需控制训练集、架构、训练预算和种子；本仓库性质版配置含 `limit_data: 5000` 等差异，现有文件不足以证明两套预训练权重是严格配对实验。
7. 只有编码器对照显示收益后，再考虑反应级监督微调和分子生成。RF/XGBoost 不提供可直接穿过它们的潜空间梯度；搜索应选择适配的黑箱方法，或另建可微代理模型。
