03 / 从阅读文件到正式运行

先检查文件，再从 YONOD 主入口启动。

任务设置文件（YAML）告诉程序读取哪张表、选择哪些输入，以及把结果存在哪里。示例文件夹用于展示；正式任务配置保存在仓库根的 config/ 下。

  1. 打开具体包的说明。

    先看 CSV 的列名和产率单位，再看 run.yaml 的注释。固定划分另看成员名单；外测另看两表的字段对应与来源核查记录。

  2. 确认独立任务配置。

    使用已准备的根 config/ 配置。也可将包内 run_from_root.yaml 复制到根 config/ 后运行；不要直接搬动阅读用的 run.yaml。改成自己的任务时，同时更新任务名、数据路径与独立结果路径。

  3. 在仓库根启动。

    初始化并激活 yonod 环境，通过 yonod.py 输入配置路径。Linux 使用后台运行方式，日志与 PID 文件保存到 logs/。每次使用19个可用逻辑 CPU，各任务依次运行，结果保存在自己的 result/<任务名>/。

启动前应确认什么？结果会写到哪里？

用于复制到仓库根 config/ 的正式设置：随机划分、固定名单、外测流程。对应文件名分别为 example_random_split_20261113.yaml、example_fixed_split_20261113.yaml 和 example_external_test_20261113.yaml。

Linux 的环境激活、19个可用逻辑 CPU 的选择、后台日志命令，以及 Windows 的 Conda Prompt 操作，见各包的操作说明。不要直接运行来源不明的旧配置，也不要让多个任务共用一个结果目录。

随机和固定划分的内测预测（out-of-fold prediction，OOF）来自未学习该条记录的相应模型；独立外测的预测来自训练表建立的模型。普通随机任务报告为 report/report.html，固定名单和外测的文件名以各包说明为准；外测报告为 report/external_test_report.html。网页报告（HTML）、文字报告（Markdown）与逐条预测应一起核对。评分中的 R² 不是“预测正确率”；产率采用0–1尺度时，平均绝对误差（MAE）乘100才是相差的产率百分点。

本次整理不启动建模，不生成描述符、训练模型或执行预测。新增固定划分和外测流程的预期输出，以各包说明为准。
