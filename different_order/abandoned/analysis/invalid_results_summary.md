# different_order 实验结果无效性总结报告

## 结论

本轮 `different_order` 实验结果无效，不能用于判断 Morgan 描述符或其他描述符的向量拼接顺序是否会影响建模结果。

核心原因是：不同任务的配置虽然修改了 `descriptors[*].columns`，但实际建模结果中所有任务的 `n_smiles_cols` 均保持为 8，未随任务名称对应的列数变化。这说明建模脚本没有真正按各任务配置中的列组合进行特征构建。

## 关键证据

### 1. 所有任务的 `n_smiles_cols` 不变

根据 `different_order/analysis/config_effect_audit.csv` 和 `different_order/analysis/metric_variation_by_descriptor_model.csv`：

- 所有任务实际报告的 `n_smiles_cols` 都是 8。
- 所有 descriptor/model 组合的 `unique_n_smiles_cols` 都是 8。
- 任务名对应的配置列数从 2 到 7 不等，但结果文件没有反映这种变化。

例如：

- 任务 `12` 的配置列数应为 2。
- 任务 `123` 的配置列数应为 3。
- 任务 `1234567` 的配置列数应为 7。

但这些任务在结果中均报告 `n_smiles_cols=8`。

### 2. `feature_dim` 未按配置列数变化

如果建模脚本正确使用了 `descriptors[*].columns`，不同任务的特征维度应随列数变化。

以 Morgan 为例，单列 Morgan 指纹维度为 1024：

- 任务 `12` 预期 Morgan 维度应约为 `2 × 1024 = 2048`。
- 任务 `123` 预期 Morgan 维度应约为 `3 × 1024 = 3072`。
- 任务 `1234567` 预期 Morgan 维度应约为 `7 × 1024 = 7168`。

但实际所有任务的 Morgan `feature_dim` 均为 8192，即 `8 × 1024`。

这表明建模实际使用的是固定的 8 个 SMILES 列，而不是任务配置中的列组合。

### 3. Morgan 结果在所有任务中完全相同

Morgan 是本实验重点关注的描述符。审计发现 Morgan 在 32 个任务中的 4 个模型指标完全一致：

| descriptor | model | 是否完全相同 |
| --- | --- | --- |
| morgan | xgb | 是 |
| morgan | rf | 是 |
| morgan | svm | 是 |
| morgan | autogluon | 是 |

这与“不同列组合或不同拼接顺序参与建模”的预期不一致。

## 问题定位

当前问题不是任务没有跑完，也不是指标文件缺失。

完整性检查显示：

- 共发现 32 个任务结果。
- 共汇总 768 行指标。
- 每个任务均包含 24 条结果，即 6 个 descriptor × 4 个 model。
- 未发现缺失的 descriptor/model 组合。

真正的问题在于建模脚本没有正确使用任务配置中的 `descriptors[*].columns` 字段。

从现有审计结果看，建模流程更可能是统一使用 `column_roles` 推导出的全部 8 个 SMILES 列进行特征构建，因此不同任务实际上使用了同一组输入特征。

## 对本轮结果的判定

本轮结果只能说明：

- 32 个任务都成功完成了建模流程。
- 每个任务都生成了完整的指标文件。
- 在当前错误建模逻辑下，多数 descriptor/model 组合结果完全一致，少数组合存在非确定性波动。

本轮结果不能说明：

- Morgan 描述符的拼接顺序是否影响结果。
- 不同分子列组合是否影响结果。
- 其他描述符是否受列顺序或列组合影响。

因此，本轮实验结果应判定为无效，不应进入正式结果分析或论文/报告结论。

## 后续建议

在重新实验前，应先修复建模脚本，使其在每个 descriptor 建模时真正使用配置文件中的 `columns` 字段。

修复后需要重新验证：

1. 不同任务的 `n_smiles_cols` 是否随任务列数变化。
2. 不同任务的 `feature_dim` 是否符合配置列数预期。
3. Morgan 在不同任务中的指标是否仍完全相同。
4. 只有通过上述检查后，才能继续进行正式的拼接顺序影响分析。

建议优先只重跑 Morgan 描述符相关任务，用最小成本确认修复是否生效。
